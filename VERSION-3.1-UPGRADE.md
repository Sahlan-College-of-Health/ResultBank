# SAHLAN Result Bank Version 3.1 Upgrade

This version was built from the uploaded current GitHub project.

## New features

1. Result Access Control for school-fee clearance.
   - Admin can lock/unlock individual students.
   - Locked students can still sign in, but cannot read results or submit carry-over applications until unlocked.
   - Firestore rules enforce the lock, not only the interface.

2. Bulk Academic Session Results.
   - Admin selects a Result Session (for example 2025/2026).
   - All students with results in that session are prepared in one operation.
   - Each student is placed on a separate A4 page with all available First and Second Semester results.
   - Admin can download the complete set as one PDF or print all pages.

3. Generated student passwords on the Admin page.
   - New account passwords are saved to the admin-only `studentCredentials` collection.
   - The Student Login Accounts table displays the generated password beside each matric number.
   - Existing Firebase passwords created before Version 3.1 cannot be recovered and will show `Not recorded (older account)`.
   - If a student changes the password later, the table continues to show the original generated password.

4. Student printing removed.
   - Students can view results and apply for carry-over rewrites when access is allowed.
   - Student Print Result / Print Transcript controls have been removed.
   - Printing functions also reject non-admin users.

5. Registrar signature only.
   - Examination Officer and Head of Department signature spaces were removed.
   - Printed results now contain one Registrar signature space.

## Deployment

You may either upload the complete Version 3.1 package or replace only the six files above using the replacement-only package.

After GitHub deployment, you MUST also publish the included `firestore.rules` in Firebase Console:

Firebase Console -> Firestore Database -> Rules -> replace the active rules -> Publish.

A GitHub copy of `firestore.rules` does not become active automatically unless your deployment workflow explicitly deploys Firestore rules.

## Existing students and result locks

Existing students do not require migration. A missing `resultLocked` field is treated as unlocked. The field is created automatically when an administrator uses Result Access Control.

## Existing passwords

Firebase Authentication does not expose users' existing passwords. Therefore Version 3.1 can only display passwords generated by Version 3.1 and stored at account-creation time. Do not delete working accounts merely to recover an old password unless you intentionally want to recreate that student's login.
